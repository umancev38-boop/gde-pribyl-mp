# Где прибыль МП — версия 0.8

## Что подготовлено
- API Node.js: регистрация, вход, профиль, тарифы, платежная история, отмена автопродления, админ-сводка.
- PostgreSQL: пользователи, подписки, платежи, аудит, данные пользователя.
- Robokassa: создание платёжной ссылки, проверка ResultURL по подписи и сумме, идемпотентная активация/продление.
- Отдельный worker для рекуррентных платежей; по умолчанию выключен.
- Render Blueprint: API + worker + PostgreSQL в отдельном наборе ресурсов, ветка `version-0.8`. Существующий сайт на `main` не меняется.

## Тарифы (начальные значения)
- Free: 0 ₽, 3 товара, 7 дней истории.
- Pro: 490 ₽/месяц, 100 товаров, 365 дней истории.
- Business: 990 ₽/месяц, 1000 товаров, 3650 дней истории.

## Локальный запуск
1. `npm install`
2. Создать PostgreSQL базу и задать `DATABASE_URL`.
3. Скопировать `.env.example` в `.env` и заполнить параметры.
4. `npm start` автоматически применит схему БД и запустит API.
5. Для рекуррентного worker использовать `npm run worker`.

## Настройка Robokassa
В личном кабинете магазина укажите:
- ResultURL: `https://ВАШ_API-ДОМЕН/api/billing/robokassa/result`, метод POST.
- SuccessURL: `https://ВАШ_API-ДОМЕН/api/billing/success`.
- FailURL: `https://ВАШ_API-ДОМЕН/api/billing/fail`.
- Алгоритм подписи должен совпадать с кодом (MD5).

В Render Environment задаются `ROBOKASSA_MERCHANT_LOGIN`, `ROBOKASSA_PASSWORD_1`, `ROBOKASSA_PASSWORD_2`, `APP_URL`, `ADMIN_EMAIL`. Секреты нельзя коммитить в Git или отправлять в чат.

Обычная оплата доступна после активации магазина и установки ключей. Рекуррентные платежи требуют отдельного согласования Robokassa. Только после одобрения установите `RECURRING_ENABLED=true`; до этого переменная должна оставаться `false`, а пользователи оплачивают период вручную. Пользовательское согласие на автопродление требуется отдельно.

## Самозанятый и чеки
В кабинете Robokassa отдельно подключите «Робочеки СМЗ» и разрешите интеграцию с приложением «Мой налог». Платёжная квитанция Robokassa сама по себе не является чеком НПД. После включения услуги проверьте регистрацию и доставку чека на тестовом платеже. См. официальную страницу: https://robokassa.com/online-check/robocheck-smz/

## Перед production
- Подключить и активировать магазин Robokassa, проверить тестовый и боевой платёж.
- Проверить ResultURL: подпись, сумму, повторные callback, выдачу/продление доступа.
- Проверить отмену автопродления, неуспешное списание и возврат.
- Утвердить оферту, политику конфиденциальности и отдельное согласие на автопродление.
- Убедиться, что цены, налоги и номенклатура чеков соответствуют вашей деятельности на НПД.

## Важные ограничения текущего этапа
API и биллинг — серверная основа. Витрина тарифов в интерфейсе, интеграция интерфейса калькулятора с API, полноценный e2e прогон на реальном магазине Robokassa и подключение WB/Ozon API ещё требуют отдельной реализации и проверки. Нельзя считать приём платежей включённым, пока магазин и секреты не настроены.
